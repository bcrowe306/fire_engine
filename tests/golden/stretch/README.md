# Signalsmith Stretch reference recordings

The output of the C++ Signalsmith Stretch 1.4.0 for every case in
`testkit.stretch_reference_cases` (`f_engine/testkit/stretch_cases.odin`), as
32-bit float WAVs, plus its speed in `TIMINGS.md`. They were made by
`tools/stretch_golden` on an Apple-silicon Mac before the C++ is removed. The
pure-Odin port (`fire:stretch`) is tested against them.

To remake them (only while the C++ is still in `vendor/signalsmith`):

```bash
./scripts/stretch.sh
odin run tools/stretch_golden -collection:fire=f_engine -o:speed -- "$(sysctl -n machdep.cpu.brand_string)"
```

## What the cases cover

- **Rates:** 0.4× to 3×.
- **Pitch:** +7, −12 and +3 semitones, and a tonality limit.
- **Formants:** factor, keep-with-pitch, and base frequency.
- **A custom frequency map.**
- **Presets:** default and cheaper, each with and without split computation.
- **Shapes:** stereo, 44.1 kHz, odd chunk sizes.
- **Modes:** flush, a mid-stream seek, and whole-buffer `exact()`.
- **Signals:** a sweep, drums and a synthetic voice, generated by
  `stretch_case_input`.

## Why the checks are spectral

A phase vocoder amplifies last-bit rounding. A tiny difference changes which
spectral peaks are chosen and how phases accumulate, so the waveforms
diverge while the sound does not. The C++ itself shows this:

- **Same Mac, input nudged by 1e-7:** in the pitch-shift cases, the waveform
  differs by −37 dB, while the spectra differ by 0.7 dB.
- **Same code and seed on Linux (GCC, x86-64) and Windows (MSVC):** the
  waveform differs by up to −23 dB from these recordings, while the spectra
  differ by at most 2.6 dB (6.2 dB for the randomised 0.4× case, whose
  generator differs between standard libraries).

So each case is checked with `testkit.spectral_distance`, the mean over
2048-sample frames of the RMS difference between log-magnitude spectra. Each
case's `tolerance` is twice the C++'s largest cross-platform distance for
that case, and at least 0.05 dB:

| Spread across platforms | Cases |
|---|---|
| ≈ 0 (≤ 0.004 dB) | rate 1, drums at 0.75×, 1.5× and 3×, tonality limit, formant only, cheaper, split, stereo, flush, seek |
| 0.06–0.5 dB | sweeps at 0.8×, 1.25× and 2×, formants kept through a pitch change, formant base, 44.1 kHz, odd chunks |
| 1–2.6 dB | sweep at 0.5×, ±pitch shifts, custom map, `exact()` |
| 6.2 dB | voice at 0.4× (random phases) |

The port is also checked block by block against the C++ for the first blocks
of each case, before rounding differences can compound. Those checks go when
the C++ does; these recordings stay.
